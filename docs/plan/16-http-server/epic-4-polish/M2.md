# M2: Error Handling & Reconnection UX

**Epic:** [Epic 4 — Polish](../epic-4-polish.md)
**Priority:** P1
**Depends on:** Epic 2 M2

## Description

Harden error handling across the frontend and provide clear user feedback for connection issues, API errors, and daemon unavailability.

## Tasks

- [x] **Connection banner**: show a persistent warning banner when WS is disconnected ("Reconnecting to daemon..." with countdown to next retry)
- [x] **API error toasts**: show transient error notifications for failed REST calls (auto-dismiss after 5s)
- [x] **Daemon unavailable state**: when daemon is down, disable mutation controls and show "Daemon offline" overlay
- [x] **Stale state indicator**: after reconnection, show "Refreshing..." while re-fetching full state
- [x] **Request timeout**: REST calls timeout after 10s with clear error message
- [x] **Graceful degradation**: if WS fails but REST works, fall back to polling `GET /api/state` every 5s
- [x] **Network error retry**: failed REST calls show "Retry" button in the error toast

## Acceptance Criteria

- Daemon restart triggers visible reconnection UI and automatic state refresh
- API errors don't leave the UI in a broken state
- All error states have clear user-facing messages
- Fallback polling works when WS is unavailable
