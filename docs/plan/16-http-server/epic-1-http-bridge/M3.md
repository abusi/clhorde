# M3: REST API — State & Health Endpoints

**Epic:** [Epic 1 — HTTP Bridge](../epic-1-http-bridge.md)
**Priority:** P0
**Depends on:** M2

## Description

Implement the read-only REST endpoints for querying daemon state, prompt info, and health checks.

## Endpoints

| Method | Path | Maps to | Description |
|--------|------|---------|-------------|
| `GET` | `/api/health` | `Ping` | Health check → `{ "status": "ok" }` |
| `GET` | `/api/state` | `GetState` | Full daemon state snapshot |
| `GET` | `/api/prompts` | `GetState` | List all prompts (extracted from state) |
| `GET` | `/api/prompts/:id` | `GetState` | Single prompt info |
| `GET` | `/api/prompts/:id/output` | `GetPromptOutput` | Full output text for a prompt |

## Tasks

- [ ] Create `src/routes.rs` with axum router setup
- [ ] Implement `GET /api/health` — send `Ping`, return `200` on `Pong`
- [ ] Implement `GET /api/state` — send `GetState`, return full `DaemonState` as JSON
- [ ] Implement `GET /api/prompts` — extract prompt list from `DaemonState`
- [ ] Implement `GET /api/prompts/:id` — filter single prompt from state, return `404` if not found
- [ ] Implement `GET /api/prompts/:id/output` — send `GetPromptOutput`, return output text
- [ ] Add consistent error response format: `{ "error": "message" }` with appropriate HTTP status codes
- [ ] Wire routes into the axum app in `main.rs`

## Acceptance Criteria

- All 5 endpoints return correct JSON responses
- Unknown prompt IDs return `404`
- Daemon disconnection returns `502 Bad Gateway`
- Responses use `Content-Type: application/json`
