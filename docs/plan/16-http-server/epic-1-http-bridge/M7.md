# M7: PTY Byte Streaming over WebSocket

**Epic:** [Epic 1 — HTTP Bridge](../epic-1-http-bridge.md)
**Priority:** P1
**Depends on:** M6

## Description

Extend the WebSocket handler to forward PTY binary frames from the daemon as base64-encoded JSON messages, enabling xterm.js rendering in the browser.

## Message Format

```json
{ "type": "PtyBytes", "prompt_id": 1, "data": "<base64-encoded bytes>" }
```

## Tasks

- [x] Detect binary PTY frames (0x01 marker) in the daemon event stream
- [x] Base64-encode the raw PTY bytes
- [x] Wrap in `PtyBytes` JSON envelope with the associated `prompt_id`
- [x] Forward to all WebSocket clients subscribed to that prompt (or all clients initially)
- [x] Add per-prompt subscription support: client sends `{ "type": "Subscribe", "prompt_id": N }` to opt into PTY bytes for a specific prompt (avoid flooding all clients with all PTY data)
- [x] Add `{ "type": "Unsubscribe", "prompt_id": N }` to stop receiving PTY bytes
- [x] Handle high-throughput PTY data — consider buffering/batching if needed to avoid WS backpressure

## Acceptance Criteria

- PTY bytes from interactive prompts arrive at WS clients in real time
- Data is valid base64, decodable by the JS frontend
- Subscribing to a specific prompt filters PTY traffic
- No data loss under normal throughput (typing, command output)
