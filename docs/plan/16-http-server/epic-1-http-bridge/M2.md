# M2: Daemon Bridge (IPC Client)

**Epic:** [Epic 1 — HTTP Bridge](../epic-1-http-bridge.md)
**Priority:** P0
**Depends on:** M1

## Description

Implement `bridge.rs` — an async IPC client that connects to the daemon Unix socket, sends `ClientRequest` messages, and receives `DaemonEvent` responses. This is the core translation layer between HTTP and the daemon protocol.

## Tasks

- [ ] Create `src/bridge.rs` with a `DaemonBridge` struct
- [ ] Connect to daemon socket using `clhorde-core::ipc` framing (length-delimited JSON frames)
- [ ] Implement `send_request(&self, req: ClientRequest) -> Result<DaemonEvent>` for request-response calls
- [ ] Implement an event subscription stream that yields `DaemonEvent` for broadcast to WebSocket clients
- [ ] Handle binary PTY frames (0x01 marker) separately from JSON frames
- [ ] Create `src/state.rs` with `AppState` holding the shared `DaemonBridge` (wrapped in `Arc` for axum state sharing)
- [ ] Add reconnection logic with backoff when daemon disconnects
- [ ] Log connection status changes via `tracing`

## Acceptance Criteria

- Bridge connects to daemon socket on startup
- Can send a `Ping` request and receive `Pong` response
- Event stream yields all `DaemonEvent` variants
- PTY binary frames are detected and routed separately
- Reconnects automatically if daemon restarts
