# M5: REST API — Configuration & Store Endpoints

**Epic:** [Epic 1 — HTTP Bridge](../epic-1-http-bridge.md)
**Priority:** P1
**Depends on:** M3

## Description

Implement REST endpoints for daemon configuration changes and prompt store management.

## Endpoints

### Configuration

| Method | Path | Maps to | Description |
|--------|------|---------|-------------|
| `PUT` | `/api/config/max-workers` | `SetMaxWorkers` | Set max worker count |
| `PUT` | `/api/config/default-mode` | `SetDefaultMode` | Set default prompt mode |
| `PUT` | `/api/prompts/:id/mode` | `SetPromptMode` | Set mode for specific prompt |

### Store

| Method | Path | Maps to | Description |
|--------|------|---------|-------------|
| `GET` | `/api/store` | `StoreList` | List persisted prompts |
| `GET` | `/api/store/count` | `StoreCount` | Counts by state |
| `GET` | `/api/store/path` | `StorePath` | Storage directory path |
| `POST` | `/api/store/drop` | `StoreDrop` | Drop prompts by filter |
| `POST` | `/api/store/keep` | `StoreKeep` | Keep prompts by filter |
| `POST` | `/api/store/clean-worktrees` | `CleanWorktrees` | Clean lingering worktrees |

## Tasks

- [ ] Implement `PUT /api/config/max-workers` — accept `{ "count": N }`, validate range 1–20
- [ ] Implement `PUT /api/config/default-mode` — accept `{ "mode": "interactive|one-shot" }`
- [ ] Implement `PUT /api/prompts/:id/mode` — accept `{ "mode": "interactive|one-shot" }`
- [ ] Implement `GET /api/store` — return list of persisted prompts
- [ ] Implement `GET /api/store/count` — return `{ "completed": N, "failed": N, "pending": N, ... }`
- [ ] Implement `GET /api/store/path` — return `{ "path": "..." }`
- [ ] Implement `POST /api/store/drop` — accept `{ "filter": "all|completed|failed|pending" }`
- [ ] Implement `POST /api/store/keep` — accept `{ "filter": "completed|failed|pending" }`
- [ ] Implement `POST /api/store/clean-worktrees` — return count of cleaned worktrees

## Acceptance Criteria

- Config changes take effect immediately in the daemon
- Store operations match CLI `clhorde-cli store` behavior
- Invalid config values (e.g., max-workers > 20) return `400`
