# M6: WebSocket Handler & Event Fan-out

**Epic:** [Epic 1 — HTTP Bridge](../epic-1-http-bridge.md)
**Priority:** P0
**Depends on:** M2

## Description

Implement the WebSocket endpoint that upgrades HTTP connections, subscribes to daemon events, and fans out real-time updates to all connected browser clients. Also supports receiving `ClientRequest` messages from clients as an alternative to REST.

## Endpoint

`GET /api/ws` — WebSocket upgrade

## Message Format

### Server → Client
```json
{ "type": "DaemonEvent", "event": { ... } }
```

### Client → Server
```json
{ "type": "ClientRequest", "request": { ... } }
```

## Tasks

- [ ] Create `src/ws.rs` with axum WebSocket upgrade handler
- [ ] On connection: subscribe to daemon event broadcast channel
- [ ] Forward all `DaemonEvent` messages to the WebSocket client as JSON
- [ ] Accept incoming `ClientRequest` JSON from the client, forward to daemon bridge
- [ ] Maintain a broadcast channel (`tokio::sync::broadcast`) in `AppState` for event fan-out
- [ ] Handle client disconnect gracefully (remove from subscribers, log)
- [ ] Handle daemon disconnect (send error message to WS clients, attempt reconnect)
- [ ] Add connection count tracking in `AppState`

## Acceptance Criteria

- Browser can connect to `ws://localhost:3120/api/ws`
- State changes (prompt added, worker started, output chunk) appear in real time
- Multiple WS clients receive the same events simultaneously
- Client can send `ClientRequest` via WS and receive the response
- Clean disconnect on client close or daemon restart
