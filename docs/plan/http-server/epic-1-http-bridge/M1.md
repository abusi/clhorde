# M1: Crate Scaffolding & CLI Args

**Epic:** [Epic 1 — HTTP Bridge](../epic-1-http-bridge.md)
**Priority:** P0
**Depends on:** None

## Description

Create the `crates/clhorde-web/` crate, add it to the workspace `Cargo.toml`, and wire up the binary entry point with CLI argument parsing and basic server startup.

## Tasks

- [ ] Create `crates/clhorde-web/Cargo.toml` with dependencies: `clhorde-core`, `axum`, `tokio`, `tower-http`, `serde_json`, `clap`, `tracing`, `tracing-subscriber`
- [ ] Add `clhorde-web` to workspace members in root `Cargo.toml`
- [ ] Create `src/main.rs` with `clap` arg parsing:
  - `--port` (default: `3120`)
  - `--host` (default: `127.0.0.1`)
  - `--static-dir` (optional, override for static file path)
  - `--daemon-socket` (optional, override for daemon socket path)
- [ ] Start `axum` server on configured host:port with a placeholder `/api/health` route returning `200 OK`
- [ ] Set up `tracing` logging consistent with other crates
- [ ] Verify `cargo build --release` compiles the new binary as `clhorde-web`

## Acceptance Criteria

- `clhorde-web --help` shows all CLI flags
- `clhorde-web` starts and responds to `GET /api/health` with `200`
- Workspace builds cleanly with the new crate
